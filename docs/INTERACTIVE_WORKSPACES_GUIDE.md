# Interactive workspaces — partner demonstration

All records, money, package relationships and operational confirmations are fictional
and stored in this browser. Start at the root: choose Standard Merchant or Pop-up Market,
then Merchant, Admin or Customer View. Switch View retains local business/event data.

## Standard Merchant

Merchant View opens Customization → Kawing Studio. The desktop workspace keeps tabs,
the focused inspector, interactive device canvas and save controls together. Long
settings scroll inside the inspector. On a phone, switch Edit settings / Live preview.

Choose Phone (390×844), Compact phone (360×800), Large phone (430×932), Tablet
(768×1024), or Desktop (1280×800). Each iframe uses the actual selected CSS viewport;
the surrounding canvas scales it to fit. Click a module, identity, gallery, or the
Menu/Rewards navigation to select its editor. Keyboard users can activate the native
module/edit buttons. The inspector names the selected section. Edits update the draft
immediately; Save design updates the shared customer Business Profile. Catalog
availability and operational admission rules remain immediate operational settings.
Unsaved drafts, restore, templates, themes and accessible module reorder are preserved.

Admin View is a business dossier with Overview, Packages, Setup review and Support.
Missing contact/category, unavailable catalog, unresolved blocking issues and an
incomplete review prevent a ready status. A paused account also needs attention.
Support moves from open to in progress to resolved; a resolution note is required.
These are local review steps, not real account approval, billing or authentication.

Customer View opens immediately using the merchant’s saved package. Screen-size and
Basic/Growth/Bespoke preview controls remain optional; Preview options opens the chooser.
Basic presents essential services; Growth adds the configured engagement modules;
Bespoke shows the full saved presentation. Preview choices do not change the saved
subscription, products, prices or operational policies. The customer frame contains the real hub, menu, cart, simulated checkout and receipt
in the selected viewport.

## Pop-up Market

Merchant View opens the shared booth map. Choose an open booth there, then use
My participation to select a fictional business and review its assigned booth,
event package, needs and issues. A merchant can request support, set load-in
information and report a problem. Requests do not verify fulfillment. Merchants
retains temporary-profile creation.

Admin View opens Vendor desk. Select/search a business (a compact selector on mobile); its dossier contains:

- Readiness derived from an assigned usable booth, active event, identity/contact,
  verified requested needs, installed/checked tent and no unresolved blocking issues.
- Business & tier separating current platform subscription from event participation.
  Event allocations preserve the existing business package and order records.
- Logistics separating requested equipment/services from verified fulfillment, with
  tent setup stages, load-in time and notes.
- Issues with severity, handling status and a required resolution note. Resolving one
  issue does not silently fulfill unrelated requirements.
- Orders using that business's real local records and the shared payment/fulfillment
  transition rules. Claims, review and confirmation remain distinct.

Map, paged booth list, layout geometry/walkway validation, undo, assignment, temporary
profiles, event lifecycle and confirmed market reset remain available.

Customer View offers map and list. Choose an occupied active booth → Open Business
Profile → immediately enter the customer experience, with optional device/tier previews. Salo reuses its existing catalog;
Luna Made has a separate craft catalog, cart, receipt and order store. Closed/reassigned
or unavailable booths reject new checkout even if the page was already open. Existing
orders can still be completed after the event ends.

## Eight-minute partner sequence

1. Standard Merchant → Merchant View. Choose a phone canvas, click Guest Wi-Fi, edit it,
   then click Menu. Change a theme/template, save and point to the selected editor.
2. Customer View. Choose 360×800 and Basic, then switch to Growth. Explain that
   these are preview projections, not subscription or payment changes.
3. Admin View. Fill missing setup details, review, report a blocker and resolve it with
   a note. Show why readiness changes from the actual configured checks.
4. Pop-up Market → Merchant View. Open Salo's Logistics, request cold storage and report
   a fictional power issue. It remains pending until the organizer verifies it.
5. Admin View. Select Salo, review current vs event tier, fulfill requested needs, move
   the tent to Installed and checked, then resolve the issue with a note.
6. Customer View. Open B02 → Business Profile, place a GCash demo order and claim sent.
   Admin Vendor desk → Orders: review, confirm, prepare, ready, serve. Return to the
   receipt; it uses the same record. No money moved.
7. Open B07 to show Luna's separate craft catalog and receipt. Return to Map to show
   the booth list, available spots and assignment options.
8. Explain the proposed three-month pilot with 3–5 establishments. Keep network
   effects, commercial packages, provider integrations and operating results labeled
   as proposals. No production assurance is implied by passing a demonstration.

## Practical limits

Desktop Studio and the customer selector fit the reviewed desktop viewport. Complex
forms and smaller screens use controlled scrolling. Device previews emulate CSS
viewport dimensions in Chromium; they do not replace tests on real iOS/Android devices.
Local storage is neither secure multi-tenant storage nor a multi-user reservation lock.
Role selection is presentation navigation. Readiness is a checklist, not legal or safety
certification. Real logistics, notifications, billing, payments, Wi-Fi provisioning,
weather response and customer identity need separate production design.
